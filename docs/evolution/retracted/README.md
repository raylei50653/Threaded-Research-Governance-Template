# Retracted designs

Three designs that were adopted, used, and withdrawn. They are kept because a model whose
history contains only additions is a model that has not yet been tested — the evidence that
an abstraction is load-bearing is that a neighbouring one was found not to be, and removed.

| | design | withdrawn | why it failed | grade |
|:--|:--|:--|:--|:--|
| **01** | [Dispatch sidecars as execution authority](01-dispatch-sidecars-as-execution-authority.md) | 2026-07-10 | Restated facts an authoritative system already owned | **V** |
| **02** | [Uniform WIP = 1](02-uniform-wip-1.md) | 2026-07-13 | Constrained execution when it meant to constrain decisions | **V** |
| **03** | [Governance coupled to development](03-governance-coupled-to-development.md) | *in flight* | One gate answering three questions | **O** |

Grading legend: [`../README.md#provenance-grading`](../README.md#provenance-grading).

> **03 is not yet a retraction.** It is a coupling identified in an open issue, with a
> proposed direction and no adjudication. It is listed here because pretending the third
> failure is already resolved would be exactly the plan-becomes-fact error the model
> exists to prevent.
